强化学习易混淆概念梳理

发表于2026-10-21|更新于2026-10-21|强化学习小知识
|总字数:5.2k|阅读时长:18分钟

读强化学习的论文和代码，最先卡住人的往往不是公式，而是这十个词：step、turn、episode、epoch、horizon、trajectory、history、return、reward、rollout。它们有的描述时间的长短，有的描述数据的形状，有的描述训练流程的哪一环；同一个词在教材、论文和代码框架里还常常不是一个意思。本文按"从小到大"的顺序，把它们一个个放到该放的位置上。

本文结构

  1. 速查表：每个词一句话。
  2. 最小单位：step 与 reward。
  3. 一整段交互：episode、trajectory、horizon。
  4. 回头看与往前看：history 与 return。
  5. 训练循环：rollout 与 epoch。
  6. LLM 场景：turn 登场。
  7. 串起来：一个数得清的例子。
  8. 常见误用清单。

符号约定：本文默认采用 Sutton & Barto《Reinforcement Learning: An Introduction》的写法，状态 StS_tSt​、动作 AtA_tAt​、执行动作后得到的奖励记作 Rt+1R_{t+1}Rt+1​，折扣因子 γ∈[0,1]\gamma \in [0, 1]γ∈[0,1]。

0 速查表

前五个和 history、return 是强化学习"问题本身"的概念，rollout 和 epoch 是"训练流程"的概念，turn 是 LLM 时代才频繁出现的概念。把这三层分清，大部分混淆就消失了。

1 最小单位：step 与 reward

1.1 step：交互循环转一圈

图源：Gymnasium 文档，Basic Usage。智能体根据观测选择动作，环境返回新的观测和奖励。

强化学习的一切都建立在这个循环上。循环转一圈，就是一个 step：

  1. 智能体处在状态 StS_tSt​（或者只看到观测 OtO_tOt​）；
  2. 按策略选出动作 At∼π(⋅∣St)A_t \sim \pi(\cdot \mid S_t)At​∼π(⋅∣St​)；
  3. 环境返回奖励 Rt+1R_{t+1}Rt+1​ 和下一个状态 St+1S_{t+1}St+1​。

一个 step 留下的数据就是一条转移（transition）(St,At,Rt+1,St+1)(S_t, A_t, R_{t+1}, S_{t+1})(St​,At​,Rt+1​,St+1​)。在代码里，step 字面上就是一次函数调用：Gymnasium 的 env.step(action) 返回 (observation, reward, terminated, truncated, info)，调用一次，时间 ttt 加一。

要小心的是，训练日志里的 “step” 不一定是这个意思。有的框架按环境步数计（智能体和环境交互了多少次，比如 Stable-Baselines3 的 total_timesteps、CleanRL 的 global_step），有的按训练步数计（做了多少轮更新，比如 verl 日志里的 step 是训练迭代次数）。两者可以差好几个数量级，看曲线横轴之前先确认是哪一个。

1.2 reward：一步的即时反馈

reward 是环境在每个 step 给出的一个标量，表示"刚才这一步好不好"。它由任务定义，智能体改变不了奖励函数本身。

  • 稠密奖励：每一步都有有意义的数值，比如机器人每前进一米加一分。
  • 稀疏奖励：绝大多数步都是 0，只在关键时刻有值，比如下棋只在终局给 +1 / −1，数学题只在答案对时给 1。

关于下标，有两种常见写法，指的是同一件事：

  • Sutton & Barto：在 StS_tSt​ 做了 AtA_tAt​ 之后拿到的奖励记作 Rt+1R_{t+1}Rt+1​，强调"奖励和下一个状态一起出现"；
  • OpenAI Spinning Up 等：记作 rt=R(st,at,st+1)r_t = R(s_t, a_t, s_{t+1})rt​=R(st​,at​,st+1​)，强调"这是第 ttt 步的奖励"。

读公式时先看作者用的是哪一种，回报的求和下标会差一位。

2 一整段交互：episode、trajectory、horizon

2.1 episode：从开局到终局

episode 是一局完整的交互：从环境 reset 得到初始状态 S0S_0S0​ 开始，一步一步走，直到进入终止状态（terminal state）为止，比如游戏结束、机器人摔倒、迷宫走到出口。终止的时刻记作 TTT，它通常是随机的，每一局都可能不同。

有终局的任务叫分幕式任务（episodic task）；没有天然终局、可以一直进行下去的任务（比如持续调度一个机房的温度）叫持续式任务（continuing task）。后者谈不上"一个 episode"，只能谈"一段时间"。

2.2 trajectory：把一段交互记下来

trajectory（轨迹）是把交互按时间顺序记下来的数据：

τ=(S0,A0,R1,S1,A1,R2,…,ST−1,AT−1,RT,ST)\tau = (S_0, A_0, R_1, S_1, A_1, R_2, \dots, S_{T-1}, A_{T-1}, R_T, S_T) τ=(S0​,A0​,R1​,S1​,A1​,R2​,…,ST−1​,AT−1​,RT​,ST​)

episode 和 trajectory 的区别在于：

  • episode 是一件事：环境里发生的一局；
  • trajectory 是一份记录：这局（或这局的一段）留下的序列，是训练时真正拿来算梯度的东西。

一条轨迹不一定是完整的一局。它可以从中途开始，也可以在终局之前被截断，后面讲 rollout 时会看到这种情况其实很常见。

这几个词之所以总被混用，是因为很多资料本来就把它们当同义词。Spinning Up 在入门篇里明确写着：“Trajectories are also frequently called episodes or rollouts.”（轨迹也常被叫作 episode 或 rollout。）所以遇到这三个词时，与其纠结字面，不如问两个问题：这段数据是不是完整的一局？它是由哪个策略产生的？

2.3 horizon：看多远，跑多长

horizon 是十个词里含义最多的一个，至少有下面五种用法。

① 问题定义里的 horizon。 有限时域（finite-horizon）问题只考虑固定的 HHH 步，目标是 ∑t=0H−1Rt+1\sum_{t=0}^{H-1} R_{t+1}∑t=0H−1​Rt+1​；无限时域（infinite-horizon）问题考虑无穷多步，靠折扣 γ<1\gamma < 1γ<1 让总和收敛。

② 折扣带来的有效视野。 在无限时域里，γ\gammaγ 决定了智能体实际"看多远"。kkk 步之后的奖励权重是 γk\gamma^kγk，常用的经验估计是

Heff≈11−γH_{\text{eff}} \approx \frac{1}{1-\gamma} Heff​≈1−γ1​

所以 γ=0.99\gamma = 0.99γ=0.99 时大约看 100 步，γ=0.9\gamma = 0.9γ=0.9 时只看 10 步左右。

③ 工程上的时间限制。 为了让训练不卡在一局里，环境通常设一个最大步数（Gymnasium 里是 max_episode_steps）。这就引出一个经典的坑：Gymnasium 把"结束"拆成了两个信号。

  • terminated=True：真的到了终止状态，之后不会再有奖励，未来价值记为 0；
  • truncated=True：只是被时间限制打断，环境本身还能继续，计算回报时应该用价值函数 V(ST)V(S_T)V(ST​) 把被截掉的未来补回来（bootstrap）。

把 truncated 当成 terminated 处理，会让智能体误以为"时间到了就没有未来"，在有时间限制的任务里学出奇怪的行为。

④ PPO 论文里的 “Horizon (T)”。 PPO 原论文的超参数表里有一行 Horizon (T)：Mujoco 实验是 2048，Atari 实验是 128。这里的 TTT 不是 episode 的长度，而是每个并行环境在一轮 rollout 里跑多少步（见 4.1）。一局 Atari 游戏动辄几千步，128 步只是其中一小段。

⑤ 规划里的 horizon。 在模型预测控制（MPC）和基于模型的规划里，planning horizon 指每次往前推演多少步。执行第一步之后，窗口整体后移再规划一次，这叫滚动时域（receding horizon）。

读到 horizon 时，先判断是这五种里的哪一种。

3 回头看与往前看：history 与 return

如果站在时刻 ttt，把一条轨迹从中间切开，左边是 history，右边决定了 return。

3.1 history：截至此刻见过的一切

history 是智能体到时刻 ttt 为止看到过的全部信息：

Ht=(O0,A0,R1,O1,A1,R2,…,At−1,Rt,Ot)H_t = (O_0, A_0, R_1, O_1, A_1, R_2, \dots, A_{t-1}, R_t, O_t) Ht​=(O0​,A0​,R1​,O1​,A1​,R2​,…,At−1​,Rt​,Ot​)

它和 trajectory 的区别是视角不同：

  • history 是策略的输入，只包含"过去"，是做决策时能用的信息；
  • trajectory 是训练的材料，事后记录，包含整段数据（也就包含了相对于每个时刻的"未来"）。

history 什么时候重要？

  • 在 MDP 里，当前状态 StS_tSt​ 已经包含了决策需要的全部信息（马尔可夫性），策略只看 StS_tSt​ 就够了，history 可以丢掉；
  • 在部分可观测的问题（POMDP）里，单个观测 OtO_tOt​ 不够用（比如一帧画面看不出球往哪飞），策略就要依赖 history，或者从 history 里压缩出一个"信念状态"；
  • 在 LLM 里，history 就是上下文窗口：系统提示、用户问题，加上模型此前的所有输出和工具返回。多轮智能体的"上下文管理"（截断、摘要、记忆），本质上就是在处理越来越长的 history。

3.2 return：从此刻往后的奖励总和

return（回报）是从时刻 ttt 往后所有奖励的折扣和：

Gt=Rt+1+γRt+2+γ2Rt+3+⋯=∑k=0∞γkRt+k+1G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} Gt​=Rt+1​+γRt+2​+γ2Rt+3​+⋯=k=0∑∞​γkRt+k+1​

分幕式任务里求和到终局 TTT 为止。它有一个很好用的递推形式：

Gt=Rt+1+γ Gt+1G_t = R_{t+1} + \gamma\, G_{t+1} Gt​=Rt+1​+γGt+1​

reward、return、value 三者的关系是：

  • reward 是一步的即时反馈，只看眼前；
  • return 是一条具体轨迹上、从 ttt 开始往后的累计奖励，是一个随机变量；
  • value 是 return 的期望：vπ(s)=Eπ[Gt∣St=s]v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]vπ​(s)=Eπ​[Gt​∣St​=s]。

两个例子可以看出 reward 和 return 为什么必须分开：

  • 下棋，γ=1\gamma = 1γ=1，只在终局给 +1（赢）或 −1（输）。中间每一步的 reward 都是 0，但每一步的 return 都等于最终胜负。强化学习要学的，正是"哪一步导致了最后的胜负"，这就是信用分配问题。
  • 走迷宫，每走一步 reward 为 −1，走出去为止。从起点开始的 return 就是"负的步数"，最大化 return 等于找最短路。

还有一个日志里的小陷阱：Stable-Baselines3 的 rollout/ep_rew_mean 名字里写的是 reward，实际记录的是每局奖励直接相加的平均值，也就是不打折扣的整局回报 ∑tRt+1\sum_{t} R_{t+1}∑t​Rt+1​，不是单步奖励，也不是训练用的折扣回报。

4 训练循环：rollout 与 epoch

前面讲的都是"问题本身"的概念。rollout 和 epoch 属于"怎么训练"。

4.1 rollout：让当前策略去环境里跑

rollout 指用当前策略和环境交互、采集数据的过程（动词用法），也指这样采到的一批数据（名词用法）。

先看 PPO 原论文的算法框架：

出处：Schulman et al., Proximal Policy Optimization Algorithms (2017), Algorithm 1。

里面那个"每个 actor 跑 TTT 步"的内层循环就是 rollout。注意它和 episode 的关系：

  • rollout 按固定步数 TTT 收集，不按局数；
  • 一局在中途结束了，环境会自动 reset，同一段 rollout 里可能包含好几局的片段；
  • 一局还没结束，rollout 也可能到点就停，留下一段被截断的轨迹（这时就要用 2.3 里说的 bootstrap）。

所以 rollout ≠ episode。rollout 是"采样这件事"，episode 是"环境里的一局"。

rollout 还有两个常见用法：

  • 蒙特卡洛树搜索里，rollout 指从某个节点出发，用一个快速策略一路模拟到终局，用结果估计这个节点的价值（AlphaGo 的快速走子网络就是干这个的）；
  • LLM 强化学习里，rollout 指"让模型对一批 prompt 生成回答"的阶段，通常交给 vLLM、SGLang 这类推理引擎完成。verl 里的 actor_rollout_ref.rollout.n 就是每个 prompt 采样几条回答，也就是 GRPO 里的组大小 GGG。

4.2 epoch：同一批数据用几遍

在 PPO 里，epoch 指把这一轮 rollout 采到的 N×TN \times TN×T 条数据完整用一遍来做梯度更新。KKK 个 epoch，就是同一批数据反复用 KKK 遍；每一遍再切成大小为 MMM 的 minibatch，每个 minibatch 做一次梯度更新。

为什么不能一直用下去？因为每更新一次，策略就离采数据的那个旧策略 πθold\pi_{\theta_\text{old}}πθold​​ 远一点，数据越来越"过时"。PPO 用裁剪把这种偏离限制住，但 KKK 也只能取个位数到十几（论文里 Atari 用 3，Mujoco 用 10）。用完 KKK 遍就把数据扔掉，回去重新 rollout。

拿论文的 Atari 设置算一遍：N=8N = 8N=8 个并行环境，每个跑 T=128T = 128T=128 步，一轮 rollout 共 8×128=10248 \times 128 = 10248×128=1024 条转移；minibatch 是 32×8=25632 \times 8 = 25632×8=256，一个 epoch 切成 4 个 minibatch；K=3K = 3K=3 个 epoch，所以每轮迭代做 12 次梯度更新。

麻烦在于，"epoch"在不同地方至少有三种意思：

出现在哪 epoch 指什么
PPO 论文、SB3 的 n_epochs、verl 的 actor.ppo_epochs 同一批 rollout 数据重复用几遍（上面的 KKK）
OpenAI Spinning Up 的 epochs / steps_per_epoch 一整轮"采样 + 更新"：先和环境交互 steps_per_epoch 步（默认 4000），再做 train_pi_iters 次梯度更新（默认 80）
verl 的 trainer.total_epochs 等 LLM 框架 沿用监督学习的意思：把整个 prompt 数据集遍历一遍

同一个 verl 配置文件里，ppo_epochs 和 total_epochs 就是两种完全不同的 epoch。

5 LLM 场景：turn 登场

把强化学习用到大模型上以后，上面这些词要重新对一次位置，并且多了一个 turn。

5.1 单轮 RLHF：一个回答就是一局

图源：Hugging Face 博客，Illustrating Reinforcement Learning from Human Feedback (RLHF)。从 prompt 数据集取出 xxx，策略模型生成回答 yyy，奖励模型打分，减去和初始模型之间的 KL 惩罚后，用 PPO 更新策略。

在单轮场景里，一个 prompt 加上模型生成的完整回答，就是一个 episode。对 step 有两种看法：

  • 把整段回答看成一个动作：状态是 prompt，动作是整段回答，奖励只有一次。这其实退化成了上下文老虎机（contextual bandit），horizon 为 1。
  • 把每个 token 看成一个动作（token 级 MDP）：状态是"prompt + 已经生成的 token"，动作是下一个 token，状态转移就是把这个 token 接到末尾。这时一个 step 就是生成一个 token，horizon 就是最大回答长度（verl 里的 data.max_response_length），奖励模型的分数一般只加在最后一个 token 上，KL 惩罚则可以逐 token 计算。

PPO 式的 RLHF 实现大多采用第二种看法，因为价值函数和优势要按 token 估计。

5.2 多轮智能体：turn 和 step 错开了

图源：Wang et al., RAGEN: Understanding Self-Evolution in LLM Agents via Multi-Turn Reinforcement Learning (2025)，图 1。左边是数学、代码这类单轮任务；右边是需要和环境多轮交互的任务，比如推箱子（Sokoban）、冰湖（FrozenLake）。

当模型要和环境（工具、网页、游戏、用户）来回交互时，就有了 turn：模型输出一次（可能包括思考和一个动作），环境回应一次（返回观测和奖励），这算一轮。

这时同一个"step"可能指三种东西：

  1. 一个 token：token 级 MDP 的视角；
  2. 一个 turn：大多数智能体论文的视角，一个 turn 等于和环境交互一次；
  3. 一次环境调用：如果模型一轮里调用了多个工具，环境侧的步数还会更多。

一个 turn 里通常有几百上千个 token，所以"horizon = 10"可能指 10 个 turn，也可能指 10 个 token，差别巨大。读多轮智能体的论文时，第一件事是确认 step 和 horizon 用的是哪种单位。

history 在这里也最直观：第 kkk 个 turn 的输入，就是初始 prompt 加上前 k−1k-1k−1 个 turn 的全部输出和环境反馈。它每过一轮就变长一截。

5.3 放进一张图里

图源：RAGEN 论文，图 2（StarPO 框架）。左边是 K 轮 rollout，产生 N 条轨迹；右边对这 N 条轨迹估计优势并更新模型。

这张图几乎把本文的词都画进去了，可以对着读：

  • s0s_0s0​：初始状态，也就是任务 prompt；
  • akTa_k^TakT​：第 kkk 个 turn 里模型的输出（思考过程 + 动作），sk+1s_{k+1}sk+1​ 是环境返回的新状态，rkr_krk​ 是这一轮的 reward；
  • 左上的 append 循环：每一轮都把输出和反馈接到输入后面，输入就是不断变长的 history；
  • 左下的 Trajectory τ\tauτ：把 KKK 个 turn 串起来的整条记录，末尾的 rall=∑irir_\text{all} = \sum_i r_irall​=∑i​ri​ 就是整条轨迹的 return（不打折扣）；
  • 标题里的 “K-turn Rollout for N Trajectories”：一次 rollout 采 NNN 条轨迹，每条最多 KKK 个 turn，KKK 就是以 turn 为单位的 horizon；
  • 右边的 Update：拿这批轨迹做一次（或几个 epoch 的）参数更新，然后回到左边重新 rollout。

  • 第 3 个 turn 开始时的 history，是题目加上前两轮的全部输出和反馈；
  • 如果某条轨迹到第 5 轮还没完成任务，它是被 horizon 截断的，不是自然终止。

7 常见误用清单

  • 把 reward 当 return。 reward 是一步，return 是从这一步往后的总和。稀疏奖励任务里，大部分步的 reward 为 0，但 return 并不为 0。
  • 把 PPO 的 TTT 当成 episode 长度。 论文里叫 Horizon (T)，实际是每个环境每轮 rollout 的步数。
  • 把 truncated 当成 terminated。 时间到了不代表没有未来，截断时要用价值函数补上剩余回报。
  • 看错日志里的 step。 先确认横轴是环境步数还是梯度更新次数。
  • 以为 epoch 只有一种意思。 PPO 的 epoch 是同一批数据用几遍；Spinning Up 的 epoch 是一轮"采样 + 更新"；LLM 框架的 total_epochs 是遍历几次 prompt 数据集。
  • 以为 rollout 就是一局。 rollout 按步数或按 prompt 批次收集，可能包含多局的片段，也可能截断一局。
  • 在多轮智能体里混用 turn 和 step。 一个 turn 里有成百上千个 token，读论文时先确认 step 和 horizon 的单位。
  • 把 history 和 trajectory 混用。 history 是做决策时的输入，只有过去；trajectory 是训练时的记录，是整段数据。
